## 🧪 测试步骤

### 1. 测试后端是否正常运行

运行测试脚本:
```cmd
test-connection.bat
```

或手动测试:
```cmd
curl http://localhost:8080/health
```

**预期结果**: 返回 `{"status":"ok"}` 或类似响应

---

### 2. 检查后端日志

在后端运行的终端查看是否有请求日志:
```
2025-12-05T... INFO  tower_http::trace: request{method=GET uri=/health ...}
```

如果没有看到请求日志，说明请求没有到达后端。

---

### 3. 检查防火墙

Windows 防火墙可能阻止了连接。临时关闭防火墙测试:
```cmd
# 以管理员身份运行
netsh advfirewall set allprofiles state off
```

测试后记得重新开启:
```cmd
netsh advfirewall set allprofiles state on
```

---

### 4. 重新构建客户端

修改了 API URL 后，需要重新构建客户端:

```cmd
cd client

# 清理构建缓存
flutter clean

# 重新获取依赖
flutter pub get

# 重新构建
flutter build windows

# 或直接运行
flutter run -d windows
```

## 🔧 常见问题

### 问题 1: 连接被拒绝 (Connection Refused)

**原因**: 后端未运行或端口不正确

**解决**:
1. 确认后端正在运行: `cargo run` 在 server 目录
2. 检查端口: 后端应该显示 `Server listening on http://0.0.0.0:8080`
3. 测试端口: `curl http://localhost:8080/health`

---

### 问题 2: 超时 (Timeout)

**原因**: 防火墙阻止或网络问题

**解决**:
1. 检查防火墙设置
2. 确认没有 VPN 或代理干扰
3. 尝试使用 `127.0.0.1` 代替 `localhost`

---

### 问题 3: CORS 错误

**原因**: 跨域请求被阻止

**解决**: 后端已配置 CORS 允许所有来源:
```rust
let cors = CorsLayer::new()
    .allow_origin(Any)
    .allow_methods(Any)
    .allow_headers(Any);
```

如果仍有问题，检查浏览器控制台的具体错误信息。

---

### 问题 4: 404 Not Found

**原因**: API 路径不正确

**解决**: 确认客户端使用的路径与后端匹配:

后端路由:
- `POST /auth/register` - 注册
- `POST /auth/login` - 登录
- `GET /health` - 健康检查
- `GET /ws` - WebSocket 连接

客户端配置:
- 基础 URL: `http://localhost:8080` ✅ (已修复)
- WebSocket: `ws://localhost:8080/ws` ✅

## 🧪 验证连接

### 使用 curl 测试

```cmd

# 注册用户

  -H "Content-Type: application/json" ^

  -H "Content-Type: application/json" ^
```

## 💡 提示

1. **使用 127.0.0.1 代替 localhost**
   
   有时 localhost 解析可能有问题，尝试:
   ```dart
   static const String baseUrl = 'http://127.0.0.1:8080';
   ```

2. **检查网络适配器**
   
   确保没有多个网络适配器干扰连接

3. **临时禁用杀毒软件**
   
   某些杀毒软件可能阻止本地连接

4. **使用网络监控工具**
   
   使用 Wireshark 或 Fiddler 查看实际的网络请求
