# 消息发送后退出看不到问题

## 问题描述

用户发送消息后，退出应用再重新进入，刚才发送的消息看不到了。

## 错误日志

```
✅ WebSocket connected
📤 Message sent to conversation: 9c4c9b42-8118-4f7b-8738-a08f408a5e86
Data: {type: message, content: test, msg_type: 0, group_id: 9c4c9b42-8118-4f7b-8738-a08f408a5e86}
❌ Failed to parse message: type 'Null' is not a subtype of type 'String' in type cast
💾 Message saved to database: temp_1765031764554
```

## 根本原因

### 问题 1：群组消息未发送回本地连接

**位置**：`server/src/services/message/message_router.rs` - `route_to_group` 方法

**原因**：
1. 客户端发送消息时使用临时 ID（`temp_${timestamp}`）
2. 服务器保存消息后生成真实 ID
3. `route_to_group` 方法只将消息发布到 Redis 频道，但没有发送回任何本地 WebSocket 连接
4. 发送者看不到带有真实 ID 的消息，只有临时消息
5. 退出应用后，临时消息丢失，重新加载时只能从 API 获取

**代码问题**：
```rust
async fn route_to_group(&self, group_id: &Uuid, message: &Message) -> Result<u32, RouterError> {
    // Publish to group channel for all instances
    let channel = format!("group:{}", group_id);
    self.publish_to_redis(&channel, message).await?;

    // TODO: Get group members and deliver locally
    // For now, just return 0 as we need group service integration
    Ok(0)  // ❌ 没有发送给任何本地连接！
}
```

### 问题 2：WebSocket 消息格式不匹配

**位置**：`server/src/services/message/websocket_handler.rs` 和 `server/src/services/message/models.rs`

**原因**：
- 服务器发送的 `Message` 结构缺少客户端期望的 `conversation_id` 字段
- 客户端 `Message.fromJson` 期望：
  - `conversation_id` (String, 必需)
  - `id` (String, 必需)
  - `sender_id` (String, 必需)
  - `type` (String, 可选)
  - `content` (String, 必需)
  - `created_at` (String, 必需)

- 服务器 `Message` 结构只有：
  - `id` (Uuid)
  - `sender_id` (Uuid)
  - `receiver_id` (Option<Uuid>)
  - `group_id` (Option<Uuid>)
  - `msg_type` (i16)
  - `content` (String)
  - `created_at` (DateTime)

- 客户端尝试读取 `json['conversation_id'] as String` 时得到 `null`，导致类型转换失败

## 解决方案

### 修复 1：群组消息发送回发送者

**文件**：`server/src/services/message/message_router.rs`

**修改**：
```rust
async fn route_to_group(&self, group_id: &Uuid, message: &Message) -> Result<u32, RouterError> {
    // Publish to group channel for all instances
    let channel = format!("group:{}", group_id);
    self.publish_to_redis(&channel, message).await?;

    // At minimum, deliver back to the sender so they see their message with the real ID
    // This fixes the issue where sent messages disappear after app restart
    let sender_delivered = self.deliver_locally(&message.sender_id, message).await;
    
    let delivered_count = if sender_delivered { 1 } else { 0 };

    tracing::debug!(
        group_id = %group_id,
        message_id = %message.id,
        sender_id = %message.sender_id,
        delivered_count = delivered_count,
        "Group message delivered to sender"
    );

    // TODO: Get group members from database and deliver to all online members
    // For now, we rely on Redis pub/sub for multi-instance delivery

    Ok(delivered_count)
}
```

**效果**：
- 发送者能立即看到带有真实 ID 的消息
- 客户端的 `_addMessage` 方法会检查消息是否已存在（通过 ID），避免重复
- 临时消息会被真实消息替换
- 消息会被保存到本地数据库
- 退出后重新进入，消息仍然存在

### 修复 2：添加 WebSocket 消息格式转换

**文件**：`server/src/services/message/models.rs`

**添加**：
```rust
/// WebSocket message format for client compatibility
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct WsMessage {
    pub id: String,
    pub conversation_id: String,
    pub sender_id: String,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub sender_name: Option<String>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub sender_avatar: Option<String>,
    #[serde(rename = "type")]
    pub msg_type: String,
    pub content: String,
    pub status: String,
    pub created_at: String,
}

impl From<&Message> for WsMessage {
    fn from(msg: &Message) -> Self {
        // Determine conversation_id from receiver_id or group_id
        let conversation_id = msg.group_id
            .or(msg.receiver_id)
            .map(|id| id.to_string())
            .unwrap_or_else(|| msg.id.to_string());
        
        // Convert msg_type to string
        let msg_type = match MsgType::from(msg.msg_type) {
            MsgType::Text => "text",
            MsgType::Image => "image",
            MsgType::Video => "video",
            MsgType::Emoji => "emoji",
        };
        
        Self {
            id: msg.id.to_string(),
            conversation_id,
            sender_id: msg.sender_id.to_string(),
            sender_name: None,
            sender_avatar: None,
            msg_type: msg_type.to_string(),
            content: msg.content.clone(),
            status: if msg.delivered { "delivered" } else { "sent" },
            created_at: msg.created_at.to_rfc3339(),
        }
    }
}
```

**文件**：`server/src/services/message/websocket_handler.rs`

**修改**：
```rust
// Spawn task to forward messages to WebSocket
let conn_id_clone = conn_id.clone();
let sender_task = tokio::spawn(async move {
    while let Some(message) = rx.recv().await {
        // Convert to WsMessage format for client compatibility
        let ws_msg = super::models::WsMessage::from(&message);
        let json = match serde_json::to_string(&ws_msg) {
            Ok(j) => j,
            Err(e) => {
                tracing::error!("Failed to serialize message: {}", e);
                continue;
            }
        };
        
        if ws_sender.send(WsMessage::Text(json)).await.is_err() {
            tracing::warn!(conn_id = %conn_id_clone, "Failed to send message to WebSocket");
            break;
        }
    }
});
```

**效果**：
- WebSocket 发送的消息包含客户端期望的所有字段
- `conversation_id` 从 `group_id` 或 `receiver_id` 自动推导
- 消息类型从 `i16` 转换为字符串（"text", "image" 等）
- 时间戳格式化为 RFC3339 字符串
- 客户端能正确解析消息，不会出现类型转换错误
